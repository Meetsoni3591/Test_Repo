# Test Cases for T1.1.1 - Enable product management for admins

Okay, I'm assuming "Enable product management for admins" means that administrators in the system should have the ability to manage (create, read, update, and delete) products within the system, and the provided "Support secure user registration, login, and checkout process" is a general context/requirement for the overall system.

Here are two detailed test cases focusing on the product management aspect, and keeping in mind the need for a secure registration, login, and checkout process:

**Test Case 1: Verify Admin User Can Create a New Product Successfully**

*   **Title:**  Create New Product - Positive Flow

*   **Description:** This test case verifies that an administrator user with the appropriate permissions can successfully create a new product within the system.  It covers all required fields and verifies correct data storage and display.

*   **Steps:**

    1.  **Pre-condition:** A valid administrator user account exists with full product management permissions. Ensure the user is logged out.
    2.  **Login:** Navigate to the admin login page (e.g., `/admin/login`).
    3.  **Login Credentials:** Enter valid admin username and password.
    4.  **Login Submission:** Click the "Login" button.
    5.  **Navigation:** After successful login, navigate to the "Product Management" section (e.g., `/admin/products`).
    6.  **Initiate Product Creation:** Click the "Add New Product" or similar button.
    7.  **Enter Product Details:**
        *   In the "Product Name" field, enter a unique and descriptive name (e.g., "Super Widget X").
        *   In the "Product Description" field, enter a detailed description of the product.
        *   In the "Category" field, select a relevant category from the dropdown (e.g., "Electronics").
        *   In the "Price" field, enter a valid numerical price (e.g., "99.99").
        *   In the "Quantity" field, enter a valid integer representing the available stock (e.g., "100").
        *   In the "Image" field, upload a valid image file for the product.
        *   In the "SKU" field, enter a unique Stock Keeping Unit (e.g., "SWX-001").
    8.  **Submit Product:** Click the "Save" or "Create Product" button.
    9.  **Post-Condition:** Remain logged in as Admin user

*   **Expected Result:**

    1.  The user is successfully logged in and redirected to the "Product Management" section.
    2.  A success message is displayed confirming the product creation (e.g., "Product 'Super Widget X' successfully created.").
    3.  The newly created product ("Super Widget X") is visible in the product list within the "Product Management" section, displaying the correct name, price, and a thumbnail of the uploaded image.
    4.  When clicking on the created product, the admin user is able to view all product details that were entered in Step 7.
    5.  The product details are correctly stored in the database, and no SQL injection or other security vulnerabilities are present.

*   **Priority:** High

**Test Case 2: Verify Admin User Cannot Create a Product With Invalid Input Fields**

*   **Title:** Create New Product - Negative Flow (Invalid Input)

*   **Description:** This test case verifies that the system correctly handles invalid input when creating a new product. It focuses on different types of input validation, ensuring that invalid data is not accepted and appropriate error messages are displayed.

*   **Steps:**

    1.  **Pre-condition:** A valid administrator user account exists with full product management permissions. Ensure the user is logged out.
    2.  **Login:** Navigate to the admin login page (e.g., `/admin/login`).
    3.  **Login Credentials:** Enter valid admin username and password.
    4.  **Login Submission:** Click the "Login" button.
    5.  **Navigation:** After successful login, navigate to the "Product Management" section (e.g., `/admin/products`).
    6.  **Initiate Product Creation:** Click the "Add New Product" or similar button.
    7.  **Enter Invalid Product Details (Test each scenario individually):**

        *   **Scenario 1: Missing Required Fields:** Leave the "Product Name" field blank.  Enter valid data for all other fields.
        *   **Scenario 2: Invalid Price:** Enter a non-numeric value (e.g., "abc") in the "Price" field.
        *   **Scenario 3: Negative Price:** Enter a negative number (e.g., "-10") in the "Price" field.
        *   **Scenario 4: Invalid Quantity:** Enter a non-integer value (e.g., "10.5") in the "Quantity" field.
        *   **Scenario 5: Invalid Image:** Attempt to upload a non-image file (e.g., a `.txt` or `.pdf` file) in the "Image" field.
        *   **Scenario 6: Duplicate SKU:** Enter a SKU that already exists for another product in the "SKU" field.

    8.  **Submit Product:** Click the "Save" or "Create Product" button.
    9.  **Post-Condition:** Remain logged in as Admin user

*   **Expected Result:**

    *   **Scenario 1 (Missing Required Fields):**
        *   A clear and specific error message is displayed indicating that the "Product Name" field is required (e.g., "Product Name is required").
        *   The product is not created.
    *   **Scenario 2 (Invalid Price):**
        *   A clear and specific error message is displayed indicating that the "Price" field must be a valid number (e.g., "Price must be a valid number").
        *   The product is not created.
    *   **Scenario 3 (Negative Price):**
        *   A clear and specific error message is displayed indicating that the "Price" field must be a positive number (e.g., "Price must be a positive number").
        *   The product is not created.
    *   **Scenario 4 (Invalid Quantity):**
        *   A clear and specific error message is displayed indicating that the "Quantity" field must be a whole number (e.g., "Quantity must be a whole number").
        *   The product is not created.
    *   **Scenario 5 (Invalid Image):**
        *   A clear and specific error message is displayed indicating that the uploaded file is not a valid image (e.g., "Invalid file type. Please upload an image file.").
        *   The product is not created.
    *   **Scenario 6 (Duplicate SKU):**
        *   A clear and specific error message is displayed indicating that the SKU is already in use (e.g., "SKU already exists. Please enter a unique SKU.").
        *   The product is not created.
    *   In all scenarios, no product is created in the database and all other fields remain filled with values that user has previously entered.

*   **Priority:** High

These test cases are a starting point and can be expanded upon to cover more edge cases, such as testing different image sizes, maximum field lengths, and more complex validation rules.  Remember to prioritize your testing efforts based on risk and impact. Also remember that registration, login, and checkout process security is important to keep in mind while testing this part of the system.
