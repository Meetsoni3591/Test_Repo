**Test Case 1: Upcoming Events Count Verification**

*   **Title:** Verify Correct Upcoming Events Count Displayed

*   **Description:** This test case verifies that the system accurately calculates and displays the number of upcoming events, ensuring no events are missed or incorrectly included in the count. This is critical for user awareness and event planning.

*   **Steps:**

    1.  **Precondition:** Ensure a clean database or test environment. Define a specific timeframe for "upcoming" events (e.g., events scheduled to start within the next 7 days).
    2.  **Setup Events:** Create the following events in the system through the admin interface or API:
        *   3 events scheduled to start within the defined "upcoming" timeframe (e.g., 3 events starting in 3 days, 5 days, and 6 days).
        *   2 events scheduled to start outside the "upcoming" timeframe (e.g., 2 events starting in 8 days and 10 days).
        *   1 event scheduled to have started yesterday.
        *   1 event with the same start date as the current date.
        3.  **Navigate to the Metrics Dashboard:** Access the Events Metrics dashboard or page where the "Upcoming Events Count" is displayed.
    4.  **Observe Upcoming Events Count:**  Note the value displayed for the "Upcoming Events Count".
    5. **Event status is updated.** Ensure that an event that has passed is no longer considered in the upcoming events count.

*   **Expected Result:**

    *   The "Upcoming Events Count" should accurately display the number of events scheduled to start within the defined timeframe.  In this scenario, the expected count should be 3.
    *   Events outside the timeframe or in the past should *not* be included in the count.
    *   Event with the same start date as the current date is considered in the upcoming event count.
    *   If an event has passed, it should no longer be counted.

*   **Priority:** High

**Test Case 2: Verify Most Popular Events Functionality**

*   **Title:** Verify the Correct Identification and Ranking of Most Popular Events

*   **Description:** This test case verifies that the system accurately identifies and ranks the "Most Popular Events" based on a defined metric (e.g., number of registrations, views, or likes). This is important for highlighting relevant and engaging events to users.

*   **Steps:**

    1.  **Precondition:** Ensure a clean database or test environment. Define a specific metric for "Popularity" (e.g., Number of Registrations). Define a ranking limit (e.g., top 5 events).
    2.  **Setup Events:** Create the following events in the system:
        *   Event A: 100 Registrations
        *   Event B: 75 Registrations
        *   Event C: 50 Registrations
        *   Event D: 25 Registrations
        *   Event E: 10 Registrations
        *   Event F: 5 Registrations
        *   Event G: 1 Registration
    3.  **Navigate to the Metrics Dashboard:** Access the Events Metrics dashboard or page where the "Most Popular Events" are displayed.
    4.  **Observe Most Popular Events:** Note the events displayed in the "Most Popular Events" section and their corresponding ranking order.
    5.  **Adjust Event Metrics:**  Increase the number of registrations for Event E to 125, making it the most popular event.
    6.  **Refresh Dashboard and Observe Changes:** Refresh the Metrics Dashboard and observe if the "Most Popular Events" listing is updated to reflect the new ranking.
    7.  **Tie Breaker Test:** Create two events with the exact same number of registrations and verify the ranking logic.

*   **Expected Result:**

    *   The "Most Popular Events" section should display a list of events ranked in descending order based on the defined popularity metric (Number of Registrations).
    *   Only the top N events (e.g., top 5) should be displayed, according to the ranking limit.
    *   In the initial setup, the events should be ranked: Event A, Event B, Event C, Event D, Event E.
    *   After adjusting Event E's registration count, the ranking should update to: Event E, Event A, Event B, Event C, Event D.
    *   Tie breakers are defined in the acceptance criteria document and the expected result follows the same logic.

*   **Priority:** High
