# Test Cases for T1.1.4 - Referrals Metrics

**Test Case 1: Referral Count Tracking**

*   **Title:** Verify Referral Count Increment When Referral Link is Shared

*   **Description:** This test case verifies that the "Number of Referrals Sent" metric is accurately incremented each time a user successfully shares a referral link with a recipient. It ensures the system correctly captures the number of outgoing referrals.

*   **Steps:**

    1.  **Pre-condition:** Ensure a valid, logged-in user account exists.
    2.  **Pre-condition:** Verify the referral tracking system is enabled and active.
    3.  Navigate to the user's referral dashboard or referral section of the application.
    4.  Note the initial "Number of Referrals Sent" displayed (e.g., 0 or a pre-existing value).
    5.  Generate a unique referral link for the user.
    6.  Share the generated referral link via email, social media, or any other available sharing method. (Simulate the share.  Do *not* require sending an actual email for testing purposes. Just simulate the sharing process)
    7.  **Important**: Wait for the system's background processes that track the sharing event to complete, or manually trigger the process if possible (e.g., using a testing API endpoint).
    8.  Refresh the referral dashboard or referral section.
    9.  Compare the updated "Number of Referrals Sent" to the initial value.

*   **Expected Result:**

    The "Number of Referrals Sent" should increment by exactly 1 from the initial value.  For example, if the initial value was 0, the updated value should be 1. If the initial value was 5, the updated value should be 6.

*   **Priority:** High (P1) - Accuracy of referral tracking is fundamental to understanding referral program performance. An incorrect count directly impacts the accuracy of subsequent calculations.

**Test Case 2: Referral Conversion Rate Calculation and Display**

*   **Title:** Verify Referral Conversion Rate Calculation and Display Accuracy

*   **Description:** This test case verifies that the "Referral Conversion Rate" is correctly calculated based on the number of referrals sent and the number of successful conversions (e.g., referred users signing up or making a purchase). It also verifies the correct display of the calculated rate.

*   **Steps:**

    1.  **Pre-condition:** Ensure a valid, logged-in user account exists with existing referrals sent.
    2.  **Pre-condition:** At least one referral link generated from the previous referrals should have been used to successfully create a new user account (a "conversion"). This will likely require setting up a test scenario where a referral link is used and the sign-up process is completed.
    3.  **Pre-condition:** The system should have a method of tracking conversions related to specific referral links.
    4.  Navigate to the user's referral dashboard or referral section of the application.
    5.  Record the "Number of Referrals Sent".  Let's call this 'S'.
    6.  Determine the number of referrals from 'S' that were successfully converted into new accounts. Let's call this 'C'.
    7.  Calculate the expected Referral Conversion Rate:  (C / S) * 100.
    8.  Compare the calculated expected conversion rate with the "Referral Conversion Rate" displayed on the dashboard.
    9.  Create a new referral account. Then convert it into a paying customer.
    10. Re-calculate the rate to see if it is updated.

*   **Expected Result:**

    The displayed "Referral Conversion Rate" should match the calculated Referral Conversion Rate ((C / S) * 100), with appropriate rounding applied (as defined in the product requirements - e.g., to two decimal places). When a customer converts, the rate must be updated.

*   **Priority:** High (P1) - The referral conversion rate is a key metric for evaluating the effectiveness of the referral program. Inaccurate calculation will lead to incorrect conclusions and potentially flawed strategic decisions.
