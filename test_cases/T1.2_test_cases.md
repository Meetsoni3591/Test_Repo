# Test Cases for T1.2 - Graphical Representations

Okay, here are two detailed test cases derived from the task "Graphical Representations", focusing on different aspects to ensure comprehensive coverage.

**Test Case 1: Bar Chart Generation and Data Accuracy for User Growth**

*   **Title:** Verify Bar Chart Generation and Data Accuracy for User Growth Over Time

*   **Description:** This test case verifies that the system correctly generates a bar chart visualizing user growth over a specified time period. It checks both the visual representation and the accuracy of the data displayed in the chart.  This test case will check for data integrity between the data source and the chart being generated.

*   **Steps:**

    1.  **Preparation:** Ensure the system has sufficient user growth data across different time periods (e.g., daily, weekly, monthly) for the last year.  Include periods with significant growth, slow growth, and potential decreases in user numbers.
    2.  **Navigation:** Navigate to the reporting/analytics section of the application.
    3.  **Chart Selection:** Select the option to generate a "Bar Chart" for "User Growth".
    4.  **Time Period Selection:** Select a specific time period (e.g., "Last 3 Months", "Last Year", "Custom Range: Jan 1, 2024 - Mar 31, 2024").
    5.  **Generate Chart:** Trigger the generation of the bar chart.
    6.  **Visual Inspection:** Visually inspect the generated chart.
        *   Verify that the chart type is indeed a bar chart.
        *   Verify that the X-axis represents the specified time period (e.g., months, weeks, days).
        *   Verify that the Y-axis represents the number of users (or a relevant metric for user growth).
        *   Verify that the bars are appropriately sized and spaced.
        *   Verify that there is a clear chart title and axis labels.
        *   Verify that the chart is responsive and renders correctly on different screen sizes and devices.
    7.  **Data Verification:**
        *   Identify the user growth value for a specific time period (e.g., "February 2024") directly from the chart (e.g., by hovering over the corresponding bar).
        *   Query the database (or relevant data source) directly to retrieve the actual user growth value for the same time period.
        *   Compare the value from the chart with the value from the data source.
        *   Repeat data verification for at least 3 different time periods (with varying growth rates).
    8.  **Edge Case - Empty Dataset:** Repeat steps 2-5, but select a time period where there is no User Growth data available.

*   **Expected Result:**

    *   The system generates a clear and visually appealing bar chart representing user growth over the selected time period.
    *   The X-axis and Y-axis are correctly labeled with appropriate units.
    *   The data displayed in the chart (height of bars) accurately reflects the actual user growth values for each time period, with a variance of no more than +/- 1%.  (This tolerance can be adjusted based on the application's requirements).
    *   The chart is responsive and renders correctly on different screen sizes and devices.
    *   The chart title is appropriate to the data being displayed
    *   **Edge Case - Empty Dataset:** A message such as 'No Data Available' will be displayed, or a blank chart with appropriate axis labels. No errors or exceptions should occur.

*   **Priority:** High

**Test Case 2: Pie Chart Generation and Data Accuracy for Event Engagement**

*   **Title:** Verify Pie Chart Generation and Data Accuracy for Event Engagement Metrics

*   **Description:** This test case focuses on verifying the generation of pie charts used to visualize event engagement metrics. It checks for correct data aggregation, accurate percentage representation, and proper labeling of chart slices.

*   **Steps:**

    1.  **Preparation:** Ensure that the system has event data available for a specific event (or set of events) with various engagement metrics recorded (e.g., "Attended", "Registered", "Viewed Details", "Shared on Social Media"). These metrics should have different values to allow for a meaningful pie chart.
    2.  **Navigation:** Navigate to the reporting/analytics section of the application.
    3.  **Chart Selection:** Select the option to generate a "Pie Chart" for "Event Engagement".
    4.  **Event Selection:** Select a specific event (or a set of events) for which to generate the pie chart.
    5.  **Metric Selection:** Choose which event engagement metrics to include in the pie chart (e.g., "Attended", "Registered", "Viewed Details").
    6.  **Generate Chart:** Trigger the generation of the pie chart.
    7.  **Visual Inspection:** Visually inspect the generated chart.
        *   Verify that the chart type is indeed a pie chart.
        *   Verify that each slice of the pie chart represents one of the selected engagement metrics.
        *   Verify that each slice is labeled with the corresponding metric name and percentage of total engagement.
        *   Verify that the slices are colored distinctly and have a clear legend for identification.
        *   Verify that the sum of all percentages equals 100% (within a reasonable rounding error, e.g., +/- 1%).
        *   Verify that the chart is responsive and renders correctly on different screen sizes and devices.
    8.  **Data Verification:**
        *   For a specific engagement metric (e.g., "Attended"), note the percentage value displayed on the pie chart slice.
        *   Query the database (or relevant data source) directly to retrieve the raw count of "Attended" event attendees and the total number of attendees for *all* the selected metrics.
        *   Calculate the percentage manually: (Attended Count / Total Count) * 100.
        *   Compare the calculated percentage with the percentage displayed on the pie chart.
        *   Repeat data verification for at least 2 other engagement metrics.
    9.  **Edge Case - Single Data Point:**  Repeat steps 2-5, but select only one Event Engagement metric.

*   **Expected Result:**

    *   The system generates a visually appealing pie chart that accurately represents the distribution of event engagement metrics.
    *   Each slice is correctly labeled with the metric name and percentage of total engagement.
    *   The sum of all percentages equals 100% (within an acceptable rounding error).
    *   The calculated percentages match the percentages displayed on the chart, with a variance of no more than +/- 1%.
    *   The chart is responsive and renders correctly on different screen sizes and devices.
    *   **Edge Case - Single Data Point:** The pie chart is displayed with a single slice representing 100%, and the correct label for the selected metric.  No errors or exceptions should occur.

*   **Priority:** High
