**Test Case 1: User Registration Alert - Email Notification Success**

*   **Title:** Successful User Registration Triggers Email Alert to Admin

*   **Description:** This test case verifies that when a new user successfully registers on the platform, an email notification is promptly and accurately sent to the designated administrator(s). This ensures the system is correctly configured to notify administrators of new user sign-ups.

*   **Steps:**

    1.  **Precondition:** Ensure that an administrative email address (e.g., qa.admin@example.com) is configured within the system's administration settings to receive new user registration alerts.
    2.  **Precondition:** Ensure the email server is running and able to send emails.
    3.  **Precondition:** Have access to the specified administrator's email inbox.
    4.  Navigate to the user registration page on the platform (e.g., `/register`).
    5.  Enter valid and unique user registration details in all required fields (e.g., First Name: Test, Last Name: User, Email: test.user123@example.com, Password: Password123).
    6.  Submit the registration form.
    7.  **Verification:**  Verify that the user is successfully registered and redirected to the appropriate post-registration page (e.g., login page, profile page).
    8.  Check the configured administrator's email inbox (e.g., qa.admin@example.com).

*   **Expected Result:**

    *   An email is received in the administrator's inbox (qa.admin@example.com) within a reasonable timeframe (e.g., 5 minutes).
    *   The email's subject line clearly indicates a new user registration (e.g., "New User Registration Notification").
    *   The email body contains the following information:
        *   The newly registered user's email address (e.g., test.user123@example.com).
        *   The newly registered user's first and last name (e.g., Test User).
        *   The date and time of registration.
        *   (Optional) A link to the user's profile within the administrative interface.
    *   The email is properly formatted and readable.
    *   The sender's email address is a valid and recognizable address associated with the platform (e.g., no-reply@platformname.com).

*   **Priority:** High (P1) - Critical for maintaining awareness of user growth and potential security concerns.  A failure here means administrators are unaware of new users.

**Test Case 2: Event Alert - Capacity Threshold Reached Trigger**

*   **Title:** Event Capacity Alert is Triggered When Threshold is Reached

*   **Description:** This test case verifies that an alert (e.g., email or in-app notification) is sent to the event organizer when the number of registrations for an event reaches a pre-defined capacity threshold (e.g., 80% of the total event capacity). This enables timely action to be taken, such as increasing capacity or closing registration.

*   **Steps:**

    1.  **Precondition:** An event has been created with a defined total capacity (e.g., 100 attendees) and a capacity alert threshold (e.g., 80%). This threshold is configurable by the event organizer.
    2.  **Precondition:** Ensure the event organizer's contact information (email address or in-app notification preferences) is correctly configured in the system.
    3.  **Precondition:** Ensure the email server is running and able to send emails (if email notification is being tested). Or ensure that the notification system is running (if in-app notification is being tested).
    4.  Register users for the event until the number of registrations reaches or slightly exceeds the capacity threshold (e.g., 80 attendees registered). You can use automated registration, or manually create each registration.
    5.  **Verification:** Check the event organizer's designated notification channel (email inbox or in-app notification center).

*   **Expected Result:**

    *   An alert is received by the event organizer (via email or in-app notification, depending on configuration) within a reasonable timeframe (e.g., 10 minutes).
    *   The alert message clearly indicates that the event has reached the capacity threshold (e.g., "Event [Event Name] - 80% Capacity Reached").
    *   The alert message includes the following information:
        *   The name of the event.
        *   The current number of registered attendees (e.g., 80).
        *   The total event capacity (e.g., 100).
        *   The percentage of capacity reached (e.g., 80%).
        *   (Optional) A link to the event's management page within the platform.
    *   The alert message is clear, concise, and actionable.
    *   If an email, the sender's email address is a valid and recognizable address associated with the platform (e.g., alerts@platformname.com).

*   **Priority:** Medium (P2) - Important for effective event management and preventing overbooking.  A failure here can lead to a poor user experience for both attendees and organizers.
