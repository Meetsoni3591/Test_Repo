**Test Case 1: HTML Structure - Page Header Verification**

*   **Title:** Verify Page Header Structure and Content

*   **Description:** This test case verifies that the page header exists, contains expected elements (specifically a heading and navigation), and the heading displays the correct text. It checks fundamental HTML structure. This is a sanity check to ensure the basic page setup is correct.

*   **Steps:**

    1.  Navigate to the application's home page.
    2.  Inspect the HTML source code or use the browser's developer tools.
    3.  Locate the `<header>` element in the HTML.
    4.  Verify that the `<header>` element contains an `<h1>` element.
    5.  Verify that the `<h1>` element contains the expected page title text (e.g., "My Awesome Application").
    6.  Verify that the `<header>` element contains a `<nav>` element.

*   **Expected Result:**

    1.  A `<header>` element exists in the DOM.
    2.  The `<header>` element contains an `<h1>` element.
    3.  The `<h1>` element contains the correct page title text (e.g., "My Awesome Application").
    4.  The `<header>` element contains a `<nav>` element.

*   **Priority:** High (Critical for page rendering)

**Test Case 2: JavaScript - Basic Form Validation (Example: Email Input)**

*   **Title:** Verify Email Field Validation in Contact Form

*   **Description:** This test case verifies that the email field in the contact form correctly validates user input. It tests that the JavaScript validation logic prevents form submission with invalid email addresses and displays an appropriate error message to the user.

*   **Steps:**

    1.  Navigate to the "Contact Us" page. (Assuming there's a Contact Us page)
    2.  Locate the email input field within the contact form.
    3.  Enter an invalid email address (e.g., "test", "test@", "test@test") into the email field.
    4.  Attempt to submit the form.
    5.  Verify that the form submission is prevented.
    6.  Verify that an error message is displayed near the email field indicating that the email address is invalid. The error message should be clear and informative (e.g., "Please enter a valid email address").
    7.  Enter a valid email address (e.g., "test@example.com") into the email field.
    8.  Attempt to submit the form.
    9.  Verify that the form either submits successfully (if other fields are also valid) or that other validation errors are displayed.  The *email* field should no longer be showing an error.

*   **Expected Result:**

    1.  Form submission is prevented when an invalid email address is entered.
    2.  A clear and informative error message is displayed to the user when an invalid email address is entered.
    3.  Form submission is allowed (with respect to the email field) when a valid email address is entered.
    4. The email field specific error message disappears when a valid email is entered.

*   **Priority:** High (Important for data integrity and user experience)
