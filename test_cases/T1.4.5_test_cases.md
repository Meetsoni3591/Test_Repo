# Test Cases for T1.4.5 - Version Control

Okay, here are two detailed test cases based on the provided "Version Control: Git & GitHub" task.  These tests cover fundamental aspects of using Git with GitHub.

**Test Case 1**

*   **Title:** Verify Successful Push to Remote GitHub Repository

*   **Description:** This test case verifies that a local Git repository can be successfully pushed to a remote GitHub repository. It ensures the basic connectivity and authorization between the local Git environment and the GitHub account.

*   **Steps:**

    1.  **Prerequisites:**
        *   A local Git repository exists with at least one commit.
        *   A GitHub account exists.
        *   A remote repository has been created on GitHub.
        *   Git is installed and configured correctly on the local machine.
        *   User has required permissions to push to the remote repository. (Owner, Collaborator)

    2.  **Clone remote repository:** In the terminal, use the command: `git clone <remote_repository_URL>` to clone the remote repository to the local machine.

    3.  **Verify working directory:** Navigate to the cloned repository directory.

    4.  **Create/Modify a file:** Create a new file (e.g., `test.txt`) or modify an existing one within the local repository.

    5.  **Stage the changes:** Use the command `git add .` to stage the created or modified file.

    6.  **Commit the changes:** Use the command `git commit -m "Test commit for push verification"`.

    7.  **Push the changes:** Use the command `git push origin main` (or `git push origin master` if 'master' is still the default branch).

    8.  **Monitor output:** Observe the output in the terminal.

    9.  **Verify on GitHub:** Navigate to the remote repository on GitHub in a web browser.
        *   Check the commit history to see the new commit.
        *   Verify the created/modified file is present and contains the expected content.

*   **Expected Result:**

    *   The `git clone` command executes successfully and creates a local copy of the repository.
    *   The `git push` command executes successfully without any errors.  The terminal output should indicate successful transfer of objects to the remote repository.
    *   The new commit is visible in the commit history of the remote repository on GitHub.
    *   The created/modified file is present in the remote repository on GitHub and contains the expected content.

*   **Priority:** High

**Test Case 2**

*   **Title:** Verify Successful Pull Request Creation and Merging

*   **Description:** This test case verifies the end-to-end workflow of creating a pull request from a branch, reviewing the changes, and merging the pull request into the main branch. It validates the collaboration aspect of Git and GitHub.

*   **Steps:**

    1.  **Prerequisites:**
        *   A GitHub repository exists (either owned or forked).
        *   The local repository is synced with the remote repository.
        *   User has required permissions to create branches and pull requests on the repository.

    2.  **Create a Branch:** In the terminal, create a new branch using the command: `git checkout -b feature/test-pull-request`.

    3.  **Make Changes:** Create a new file or modify an existing one within the local repository. (e.g., add a line to a README file).

    4.  **Stage and Commit:** Stage and commit the changes using the commands:
        *   `git add .`
        *   `git commit -m "Adding a test change for pull request"`

    5.  **Push the Branch:** Push the new branch to the remote repository using the command: `git push origin feature/test-pull-request`.

    6.  **Create Pull Request:**
        *   Navigate to the GitHub repository in a web browser.
        *   Locate the banner that prompts you to create a pull request for the newly pushed branch (usually at the top of the repository page).
        *   Click "Compare & pull request".
        *   Provide a descriptive title and description for the pull request.
        *   Click "Create pull request".

    7.  **Review Pull Request (Simulated):**
        *   As a simulated reviewer, examine the "Files changed" tab in the pull request.
        *   Verify that the changes are correct and as expected.
        *   (Optional) Add comments to the pull request, simulating feedback.

    8.  **Merge Pull Request:**
        *   Click the "Merge pull request" button.
        *   Confirm the merge by clicking "Confirm merge".  (Or Squash and Merge or Rebase and Merge based on repository settings).
        *   (Optional) Delete the branch (`feature/test-pull-request`) after merging.

    9.  **Update Local Repository:**
        *   In the terminal, switch back to the main branch: `git checkout main` (or `git checkout master`).
        *   Pull the latest changes from the remote repository: `git pull origin main` (or `git pull origin master`).

    10. **Verify Changes:**
        *   Verify that the changes made in the pull request are now present in the local main branch.

*   **Expected Result:**

    *   The new branch is successfully created locally and pushed to the remote repository.
    *   The pull request is created successfully on GitHub with the provided title and description.
    *   The changes are accurately reflected in the "Files changed" tab of the pull request.
    *   The pull request is merged successfully without any conflicts.
    *   The local main branch is updated with the merged changes after the pull operation.
    *   The changes made in the pull request are present in the local main branch.

*   **Priority:** High
