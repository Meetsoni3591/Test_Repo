# Test Cases for T1.5.1 - Fully functional E-commerce website

Okay, I can provide two detailed test cases for a fully functional E-commerce website based on the general "Fully Functional E-commerce Website" title.  Since the provided description is blank, I will assume we are testing the core shopping flow.

Here are the two test cases:

**Test Case 1: Add Product to Cart and Update Quantity**

*   **Title:** Verify Adding a Product to Cart and Updating Quantity within the Cart
*   **Description:** This test case verifies that a user can successfully add a product to the shopping cart from the product details page and then modify the quantity of that product within the shopping cart.
*   **Steps:**

    1.  Navigate to the e-commerce website homepage.
    2.  Use the search bar or browse categories to locate a product.
    3.  Click on the product to navigate to the product details page.
    4.  Verify that the product details page displays product information (name, description, price, image(s), availability).
    5.  Select any necessary product options (size, color, etc.), if applicable.
    6.  Click the "Add to Cart" button.
    7.  A notification or confirmation (e.g., a mini-cart popup or a success message) should appear indicating the product has been added to the cart.
    8.  Navigate to the Shopping Cart page (e.g., by clicking a "View Cart" button or a cart icon).
    9.  Verify the product is displayed in the shopping cart with the correct product details (name, image, selected options).
    10. Locate the quantity field/selector for the added product.
    11. Increase the quantity of the product using the increment button/dropdown to increase the quantity by 2.
    12. Verify the cart subtotal updates correctly to reflect the new quantity.
    13. Decrease the quantity of the product using the decrement button/dropdown to decrease the quantity by 1.
    14. Verify the cart subtotal updates correctly to reflect the new quantity.

*   **Expected Result:**

    1.  User is able to successfully navigate to the product details page.
    2.  Product details are accurately displayed on the product details page.
    3.  The "Add to Cart" button is functional.
    4.  A clear confirmation message is displayed after adding the product to the cart.
    5.  The Shopping Cart page correctly displays the added product with all relevant details.
    6.  The quantity field/selector is functional and allows for increasing and decreasing the product quantity.
    7.  The cart subtotal is accurately updated in real-time after each quantity change.
    8.  The quantity in the cart is the quantity that was selected.

*   **Priority:** High

**Test Case 2: Checkout Process - Successful Order Placement**

*   **Title:** Verify Successful Order Placement through the Checkout Process
*   **Description:** This test case verifies that a user can successfully complete the checkout process, including providing shipping information, selecting a payment method, and placing the order.
*   **Steps:**

    1.  Navigate to the e-commerce website.
    2.  Add at least one product to the shopping cart (following steps similar to Test Case 1).
    3.  Navigate to the Shopping Cart page.
    4.  Verify the cart contents are correct (product(s), quantities, prices).
    5.  Click the "Checkout" button or similar call to action.
    6.  Enter valid shipping address information (name, address, city, state/province, zip code, country, phone number).
    7.  Click "Continue to Shipping" or similar button.
    8.  Select a shipping method from the available options.
    9.  Click "Continue to Payment" or similar button.
    10. Select a payment method (e.g., credit card, PayPal).  For credit card, enter valid test credit card details (number, expiration date, CVV, billing address).
    11. Review the order summary, including product details, shipping address, billing address, shipping method, and total amount.
    12. Click "Place Order" or "Confirm Order" button.
    13. The user should be redirected to an order confirmation page.
    14. Verify the order confirmation page displays the order number, order details (products, quantities, shipping address, billing address), and estimated delivery date.
    15. Verify that an order confirmation email is sent to the email address provided during checkout.

*   **Expected Result:**

    1.  The "Checkout" button on the Shopping Cart page is functional.
    2.  The Shipping Information form is displayed, and all fields are validated (required fields, format validation).
    3.  The Shipping Method selection page is displayed, and available shipping methods are presented with associated costs.
    4.  The Payment Method selection page is displayed, and the selected payment method form is displayed.
    5.  The credit card form accepts valid card details.
    6.  The order summary accurately displays all order details.
    7.  The "Place Order" button is functional.
    8.  The user is successfully redirected to an order confirmation page.
    9.  The order confirmation page displays all order details correctly.
    10. An order confirmation email is sent to the provided email address.
    11. The quantity of the order products in the database is reduced to reflect the purchase.

*   **Priority:** High

**Explanation of Considerations:**

*   **Priority:** Both of these test cases are marked as "High" because they represent core functionality of an e-commerce website.  If either of these fails, the user cannot effectively purchase items, which is a critical issue.
*   **Valid Data:** These test cases assume the availability of valid test data (e.g., shipping addresses, test credit card numbers) for testing payment processing without actually incurring charges.  It is important to have access to such test data in a QA environment.
*   **Negative Testing:** These test cases focus on positive flows (successful addition to cart and successful checkout).  Additional test cases would be needed to cover negative scenarios (e.g., invalid data in the checkout forms, insufficient stock, expired credit cards, etc.).
*   **Edge Cases:** Further test cases should be created to test edge cases, such as adding a large quantity of products, applying discount codes, or interacting with customer support during the checkout process.
*   **Specific UI:** The steps use generic wording for buttons and form labels ("Add to Cart," "Checkout," etc.).  In real test cases, you would use the *exact* wording from the website being tested.
*   **Email Verification:**  Confirming that the order confirmation email is received is vital.  This often involves checking an email server logs or a dedicated test email account.
*   **Database Verification:** Verifying changes to the products database after the purchase ensures that the website is properly integrated with the stock system.

These two test cases provide a solid foundation for testing the core e-commerce functionality. Remember to expand on these with more detailed and specific test cases based on the particular features and requirements of your specific e-commerce website.
