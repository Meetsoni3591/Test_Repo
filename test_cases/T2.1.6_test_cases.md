# Test Cases for T2.1.6 - Venue Performance Metrics Restaurant

**Test Case 1**

*   **Title:** Verify Total Bookings Calculation and Display for Venue Performance Metrics

*   **Description:** This test case verifies the accuracy of the Total Bookings calculation within the Venue Performance Metrics dashboard and its correct display to the restaurant user.  Accuracy and completeness are critical for business planning.

*   **Steps:**

    1.  **Setup:**
        *   Log in to the application as a restaurant user with access to the Venue Performance Metrics dashboard.
        *   Ensure the venue has a defined period selected for the metrics display (e.g., "Last 7 Days," "This Month," "Custom Range").
        *   Populate the system with at least 10 bookings through the booking system (either manual entry or through a simulated API call).  Ensure these bookings have varied guest counts and booking times within the selected period. Make sure bookings have different statuses (Confirmed, Cancelled, Completed).
    2.  **Navigate:**
        *   Navigate to the Venue Performance Metrics dashboard.
    3.  **Observe:**
        *   Locate the "Total Bookings" metric on the dashboard.
        *   Note the displayed number of total bookings.
    4.  **Manual Verification:**
        *   Query the database (using appropriate SQL) to retrieve all confirmed and completed bookings (Exclude cancelled bookings) for the same venue and within the same selected time period.
        *   Manually count the number of retrieved bookings from the database query result.
    5.  **Compare:**
        *   Compare the "Total Bookings" displayed on the dashboard with the manually counted booking total from the database.
    6.  **Repeat (Time Range Variation):**
        *   Change the selected time period in the Venue Performance Metrics dashboard (e.g., from "Last 7 Days" to "This Month").
        *   Repeat steps 3-5 for the new time period, ensuring the database query is adjusted accordingly.
    7.  **Repeat (Multiple Bookings):**
        *   Create 20 new bookings with different statuses and repeat the process.
*   **Expected Result:**

    *   The "Total Bookings" metric displayed on the Venue Performance Metrics dashboard should accurately reflect the total number of confirmed and completed bookings for the selected venue and time period, as verified against the direct database query. There should be no discrepancies.
    *   Changing the time period on the dashboard should dynamically update the "Total Bookings" metric to reflect the correct count for the new period, maintaining accuracy.

*   **Priority:** High - This metric directly impacts revenue tracking and management decisions.

**Test Case 2**

*   **Title:** Verify Integration with Google Docs for Settlements and Data Export Functionality

*   **Description:** This test case verifies that the Venue Performance Metrics data, specifically relevant for settlement purposes, can be successfully exported to and integrated with a Google Docs spreadsheet. This functionality is critical for simplifying settlement processes and reducing manual data entry.

*   **Steps:**

    1.  **Setup:**
        *   Log in to the application as a restaurant user with appropriate permissions for accessing and exporting Venue Performance Metrics data.
        *   Ensure the Google Docs integration is properly configured and authenticated within the application settings.  This may involve providing Google account credentials and granting necessary permissions.
        *   Populate the system with at least 5 confirmed and completed bookings, each with varying "Total Spend" values. Include bookings with discounts and taxes to ensure these values are also correctly exported.
    2.  **Navigate:**
        *   Navigate to the Venue Performance Metrics dashboard.
    3.  **Select Date Range & Data:**
        *   Choose a relevant date range.
        *   Within the dashboard, locate the "Export to Google Docs" or similar button/option for settlements.
    4.  **Initiate Export:**
        *   Click the "Export to Google Docs" button.
        *   If prompted, specify a name for the Google Docs spreadsheet or accept the default name.
    5.  **Verify Google Docs Creation:**
        *   Open Google Drive in a separate browser tab/window, using the same Google account that's integrated with the application.
        *   Verify that a new Google Docs spreadsheet has been created with the specified or default name.
    6.  **Data Validation:**
        *   Open the newly created Google Docs spreadsheet.
        *   Verify the following:
            *   The spreadsheet contains a header row with appropriate column labels (e.g., Booking ID, Booking Date, Guest Name, Total Spend, Discount, Tax, Settlement Amount, Booking Status).
            *   The data rows in the spreadsheet accurately reflect the booking details and calculated values from the Venue Performance Metrics dashboard for the selected date range.  Pay close attention to Total Spend, Discount, Tax, and the derived Settlement Amount.
            *   Ensure the exported data matches with the displayed values for each booking within the selected date range in the Venue Performance Metrics dashboard.
    7.  **Negative Testing:**
        *   Revoke access from google account from application.
        *   Try to export the google sheet with no access.
        *   Verify error message shown is relevent.
*   **Expected Result:**

    *   Clicking the "Export to Google Docs" button should successfully create a new Google Docs spreadsheet in the user's designated Google Drive account.
    *   The spreadsheet should contain accurate and complete data relevant for settlement, including booking details, total spend, discounts, taxes, and the calculated settlement amount for each booking within the selected date range.
    *   All data should be properly formatted within the spreadsheet, with clear header rows and consistent data types.
    *   If no access is provided, proper and understandable error message should be shown.

*   **Priority:** High - This streamlines settlement processes and reduces manual effort, directly impacting operational efficiency.
