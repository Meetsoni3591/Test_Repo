# Test Cases for T2.1 - Venue Profiles Restaurant

Okay, here are two detailed test cases for creating and updating venue profiles for restaurants, keeping in mind the perspective of a Senior QA Engineer:

**Test Case 1: Create New Restaurant Venue Profile - Valid Data**

*   **Title:** Create Restaurant Venue Profile - Valid Data & All Required Fields

*   **Description:** This test case verifies the successful creation of a new restaurant venue profile using valid input data for all required fields. It ensures the system correctly processes and stores the data, and that the created profile is accessible and displayed as expected.

*   **Steps:**

    1.  **Navigate:** From the application's main dashboard, navigate to the "Venue Management" section and then to the "Create New Venue" page.
    2.  **Select Venue Type:** Select "Restaurant" as the venue type.
    3.  **Input Basic Information:**
        *   Enter a valid and unique restaurant name (e.g., "The Spicy Spoon").
        *   Enter a valid address in the address fields (Street Address, City, State, Zip Code, Country).
        *   Select a valid Cuisine type (e.g., "Indian").
        *   Enter a valid phone number.
        *   Enter a valid email address for the restaurant.
        *   Enter a valid website URL (if applicable).
    4.  **Input Description Details:**
        *   Enter a brief description for the restaurant (within the character limit).
        *   Enter detailed Description (within the character limit).
    5.  **Input Business Hours:**
        *   Set business hours for each day of the week, ensuring that the closing time is later than the opening time. Consider including closed days.
    6.  **Upload Media:**
        *   Upload a high-quality image for the restaurant logo.
        *   Upload at least three high-quality images showcasing the restaurant's interior and food.
    7.  **Add Menu:**
        *   Create a new menu section and add menu items with names, descriptions, and prices.
    8.  **Submit Form:** Click the "Save" or "Create Venue" button.

*   **Expected Result:**

    1.  A success message should be displayed confirming the successful creation of the restaurant venue profile. (e.g., "Restaurant profile created successfully!")
    2.  The user should be redirected to the newly created restaurant's venue profile page.
    3.  All the information entered in the form should be accurately displayed on the profile page.
    4.  The restaurant should be searchable within the venue management system by its name, address, and cuisine type.
    5.  The restaurant's logo and images should be correctly displayed on the profile page.
    6.  The restaurant's business hours should be accurately displayed for each day of the week.
    7.  The menu section should be visible with all menu items, names, prices, and descriptions accurately displayed.
    8.  Database verification: The data is stored correctly in the database in relevant tables.

*   **Priority:** High

**Test Case 2: Update Restaurant Venue Profile - Invalid Data & Boundary Conditions**

*   **Title:** Update Existing Restaurant Venue Profile - Invalid Data and Boundary Conditions

*   **Description:** This test case verifies the system's behavior when attempting to update an existing restaurant venue profile with invalid data, boundary conditions, and exceeding character limits. It ensures that proper validation is in place and that the system handles errors gracefully, preventing data corruption and maintaining data integrity.

*   **Steps:**

    1.  **Navigate:** From the application's main dashboard, navigate to the "Venue Management" section and locate an existing restaurant venue profile that was previously created.
    2.  **Access Edit Mode:** Click the "Edit" or "Update" button associated with the selected restaurant profile.
    3.  **Modify Fields with Invalid Data:**
        *   Attempt to change the restaurant name to an empty string.
        *   Enter an invalid email address (e.g., missing @ symbol, invalid domain).
        *   Enter an invalid phone number (e.g., incorrect format, missing digits, invalid characters).
        *   Enter address values with special characters.
        *   Attempt to enter a description exceeding the maximum character limit.
        *   Enter price values for menu items with non-numeric characters.
    4.  **Business Hours Manipulation:**
        *   Set the closing time earlier than the opening time for a specific day.
    5.  **Image Upload Failure:**
        *   Attempt to upload a file that is not a supported image format (e.g., a .txt file).
        *   Attempt to upload an image that exceeds the maximum allowed file size.
    6.  **Remove Required Data:**
        *   Remove all the images on the image gallery section.
        *   Remove the added menu and leave empty
    7.  **Submit Form:** Click the "Save" or "Update Venue" button.

*   **Expected Result:**

    1.  Appropriate error messages should be displayed for each field containing invalid data. These error messages should be clear, concise, and informative, guiding the user on how to correct the input.
    2.  The system should prevent the user from saving the changes until all invalid data is corrected.
    3.  The restaurant name field should display an error message indicating that a name is required.
    4.  The email address field should display an error message indicating that the email format is invalid.
    5.  The phone number field should display an error message indicating that the number format is invalid.
    6.  The description field should not allow input beyond the maximum character limit. If the limit is exceeded, a clear message should indicate how many characters exceed the allowed maximum.
    7.  Submitting the business hours with closing time earlier than opening time should display a validation error.
    8.  Attempting to upload an invalid file type or exceeding the maximum file size should display an error message, and the upload should be rejected.
    9.  The system should prevent the user from submitting without any images on the image gallery section.
    10. The system should prevent the user from submitting without adding any menu item.
    11. No data corruption should occur; the existing restaurant profile should remain unchanged with its original, valid data.
    12. Database verification: The database should not be updated with any of the invalid data.

*   **Priority:** High
