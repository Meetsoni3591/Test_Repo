# Test Cases for T2.2.3 - Business Agreement Details Clubbing

Okay, I'm ready to craft some detailed test cases. Here are two test cases focusing on the "Business Agreement Details Clubbing" task, specifically addressing the addition of commission structure and discount rates.

**Test Case 1:  Successful Addition and Validation of Commission Structure**

*   **Title:** Verify Successful Addition and Validation of Commission Structure to Business Agreement

*   **Description:** This test case verifies that a user can successfully add a commission structure to a business agreement and that the system correctly stores and displays the commission details.  It also confirms that data validation rules are enforced to prevent invalid commission data from being saved.

*   **Steps:**

    1.  **Pre-condition:** User is logged in with appropriate privileges to modify business agreements. A valid, existing business agreement is selected or created.
    2.  Navigate to the "Business Agreements" section.
    3.  Select the target business agreement from the list (or create a new one).
    4.  Navigate to the "Commission Structure" tab/section within the business agreement details.
    5.  Click the "Add Commission Structure" button (or equivalent).
    6.  Enter the following valid commission details:
        *   **Commission Type:** (e.g., Percentage, Fixed Amount) - *Select from dropdown menu.*
        *   **Commission Value:** (e.g., 10, 50.00, 1000) - *Enter a valid numeric value.*
        *   **Commission Start Date:** (e.g., 2023-11-02) - *Select a valid date from date picker.*
        *   **Commission End Date:** (e.g., 2024-11-02) - *Select a valid date from date picker.*
        *   **Applicable Product/Service:** (e.g., "Product A", "Service B") - *Select from dropdown menu or free text field.*
        *   **Criteria (if applicable):** (e.g., "Sales Volume >= 100", "New Customer Acquisition") - *Enter criteria based on the specific implementation.*
        *   **Currency (if applicable):** (e.g., USD, EUR) - *Select from dropdown menu.*
    7.  Click the "Save" or "Submit" button.
    8.  **Verify data consistency:** Reopen the business agreement details.
    9.  Navigate to the "Commission Structure" tab/section.

*   **Expected Result:**

    1.  The commission structure should be successfully added to the business agreement.
    2.  A success message (e.g., "Commission structure added successfully.") should be displayed to the user.
    3.  The commission structure details (Commission Type, Value, Start Date, End Date, Applicable Product/Service, Criteria, Currency (if any)) should be accurately displayed in the "Commission Structure" table/section.
    4.  The Commission structure should be visible when searching for the same Business Agreement.
    5.  Ensure correct validation of each of the fields that the user entered (e.g., Date validations, Null validations).
    6.  Commission values are displayed accurately.

*   **Priority:** High

**Test Case 2: Verify Error Handling for Invalid Discount Rate Input**

*   **Title:** Verify Error Handling for Invalid Discount Rate Input During Business Agreement Modification

*   **Description:** This test case validates that the system correctly handles invalid input for discount rates. It ensures appropriate error messages are displayed and that invalid data is not saved to the business agreement.

*   **Steps:**

    1.  **Pre-condition:** User is logged in with appropriate privileges to modify business agreements. A valid, existing business agreement is selected or created.
    2.  Navigate to the "Business Agreements" section.
    3.  Select the target business agreement from the list (or create a new one).
    4.  Navigate to the "Discount Rates" tab/section within the business agreement details.
    5.  Click the "Add Discount Rate" button (or equivalent).
    6.  Enter the following invalid discount rate details for **ONE** of these scenarios at a time:
        *   **Scenario 1: Invalid Discount Rate Value:**  Enter a non-numeric value (e.g., "abc", "twenty") in the "Discount Rate" field.
        *   **Scenario 2: Discount Rate Out of Range:** Enter a discount rate value outside the allowed range (e.g., -10, 150 if the range is 0-100).
        *   **Scenario 3: Missing Required Field:** Leave a required field (e.g., "Discount Rate", "Start Date") blank.
        *   **Scenario 4: Invalid Date Format:** Enter an invalid date format for "Start Date" or "End Date" (e.g., "11/32/2023", "November 3, 2023" instead of "2023-11-03").
        *   **Scenario 5: End Date Before Start Date:** Enter an "End Date" that is earlier than the "Start Date".
    7.  Enter valid data in the remaining valid fields, as necessary.
    8.  Click the "Save" or "Submit" button.

*   **Expected Result:**

    1.  The system should **NOT** save the discount rate details.
    2.  An appropriate error message should be displayed to the user, clearly indicating the invalid input and the reason for the error.  The error message should be specific to the field and the type of error.
        *   **Scenario 1:** Error message similar to: "Discount Rate must be a valid number."
        *   **Scenario 2:** Error message similar to: "Discount Rate must be between 0 and 100."
        *   **Scenario 3:** Error message similar to: "Discount Rate is a required field."
        *   **Scenario 4:** Error message similar to: "Invalid date format. Please use YYYY-MM-DD."
        *   **Scenario 5:** Error message similar to: "End Date must be after Start Date."
    3.  The error message should be displayed near the invalid field (if possible).
    4.  The incorrect data should be highlighted or marked in some way.
    5.  The user should remain on the "Add Discount Rate" screen to correct the invalid input.
    6. Ensure that the Save button is disabled if there are validation errors.

*   **Priority:** High
