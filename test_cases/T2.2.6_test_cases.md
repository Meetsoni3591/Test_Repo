# Test Cases for T2.2.6 - Create/Update Events

Okay, I'm ready to craft some detailed test cases based on the "Create/Update Events" task.  Here are two test cases covering different aspects of the functionality, keeping in mind that as a senior QA engineer, I prioritize comprehensive testing and clear, reproducible steps.

**Test Case 1: Successful Event Creation with All Available Options**

*   **Title:** Create a New Event with All Available Options Enabled

*   **Description:** This test case verifies that a user can successfully create a new event with all available optional fields populated, including guestlist, table bookings, discount details, and creatives. It ensures that all data is saved correctly and the event is displayed as expected.

*   **Steps:**

    1.  **Login:** Log into the application as a user with event creation permissions.
    2.  **Navigate:** Navigate to the "Events" or "Create Event" section of the application.
    3.  **Initiate Creation:** Click on the "Create New Event" button.
    4.  **Enter Event Name:** Enter a valid event name (e.g., "Summer Music Festival").
    5.  **Set Date & Time:** Set a future date and time for the event (e.g., August 12, 2024, 7:00 PM).
    6.  **Enter Venue:** Enter a valid venue name (e.g., "Central Park Amphitheater") and address details.
    7.  **Enter Event Description:**  Enter a detailed description of the event (e.g., "A night of live music featuring top artists, food trucks, and entertainment for all ages.").  Ensure the description is within any specified character limits.
    8.  **Enable Guestlist:** Select "Guestlist Available" and specify any related settings (e.g., guest limit per user, approval process).
    9.  **Enable Table Bookings:** Select "Table Bookings Available" and specify any related settings (e.g., table price, table capacity, table layout).
    10. **Enter Discount Details:** Enter discount details including discount code, percentage/amount of discount, and a valid date range for the discount.
    11. **Upload Creatives:** Upload an appropriate image file for the event (e.g., a poster image) and video files (if applicable) in the allowed formats (e.g., JPG, PNG, MP4).
    12. **Enter Description/Caption:** Enter a description/caption to the creatives uploaded.
    13. **Save Event:** Click the "Save" or "Create Event" button.
    14. **Verification:** Navigate to the "Events" or "Manage Events" section and locate the newly created event.

*   **Expected Result:**

    1.  The application should successfully create the event without any errors or exceptions.
    2.  The user should be redirected to the event details page or a confirmation message.
    3.  The newly created event should be visible in the event list with the correct event name, date, time, and venue.
    4.  When viewing the event details, all entered information (description, guestlist settings, table booking settings, discount details, uploaded creatives, and description) should be accurately displayed.
    5.  The uploaded creatives should be correctly displayed on the event details page.
    6.  The Guestlist and Table Bookings functionalities should be enabled and configured according to the settings defined during creation.

*   **Priority:** High

**Test Case 2: Event Creation with Validation and Boundary Conditions**

*   **Title:** Event Creation - Validation of Input Fields and Boundary Conditions

*   **Description:** This test case verifies that the application correctly validates input fields during event creation and handles boundary conditions appropriately. It focuses on testing the limits of input fields, required fields, and invalid data entries.

*   **Steps:**

    1.  **Login:** Log into the application as a user with event creation permissions.
    2.  **Navigate:** Navigate to the "Events" or "Create Event" section of the application.
    3.  **Initiate Creation:** Click on the "Create New Event" button.
    4.  **Leave Required Fields Empty:** Attempt to save the event without filling in required fields such as "Event Name", "Date", "Time", and "Venue".
    5.  **Enter Invalid Date/Time:** Enter an invalid date format (e.g., "02/30/2024") or a past date. Enter Invalid time format, e.g. "25:00".
    6.  **Enter Long Event Name/Description:** Enter an event name and/or description that exceeds the maximum allowed character limit. (Check for character limit first to input the name/description correctly).
    7.  **Enter Invalid Venue:** Enter an invalid venue address. Test special characters to test for SQL injection.
    8.  **Upload Incorrect File Types:** Attempt to upload images/videos of unsupported file types (e.g., .exe, .txt).
    9.  **Upload Large File Sizes:** Attempt to upload creatives with large file sizes exceeding the permitted limit. (Check file size limit first to input the correct file size).
    10. **Enter Invalid Discount Code:** Enter a discount code that doesn't meet the criteria (e.g., special characters where only alphanumeric are allowed, too short).
    11. **Save Event:** Click the "Save" or "Create Event" button.
    12. **Verification:**  Observe the application's response to each invalid input.

*   **Expected Result:**

    1.  **Required Fields:** The application should display clear and informative error messages indicating which required fields are missing. The event should not be created until these fields are filled.
    2.  **Invalid Date/Time:** The application should display an error message indicating that the entered date/time is invalid or in the past. The event should not be saved.
    3.  **Long Event Name/Description:** The application should either:
        *   Display an error message indicating that the maximum character limit has been exceeded.
        *   Truncate the input to the maximum allowed characters and save the truncated version (with proper notification to the user).
    4.  **Invalid Venue:** The application should validate the venue address and throw an appropriate error if it is invalid. SQL injection shouldn't be possible and the appropriate error is thrown.
    5.  **Incorrect File Types:** The application should display an error message indicating that the uploaded file type is not supported. The file should not be uploaded.
    6.  **Large File Sizes:** The application should display an error message indicating that the file size exceeds the permitted limit. The file should not be uploaded.
    7.  **Invalid Discount Code:** The application should display an error message specifying the criteria for the discount code and why the entered code is invalid.
    8.  The application should NOT crash or throw unexpected errors due to invalid input.

*   **Priority:** High
