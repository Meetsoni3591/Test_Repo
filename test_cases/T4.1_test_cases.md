# Test Cases for T4.1 - Guestlist Notifications

Okay, here are two detailed test cases for the "Guestlist Notifications" feature, focusing on different aspects of the notification implementation.  I've tried to cover crucial scenarios and provide clear, actionable steps.

**Test Case 1: Confirmation Notification - Guest Perspective**

*   **Title:** Verify Guest Receives Confirmation Notification After Host Acceptance

*   **Description:** This test case verifies that a guest receives a confirmation notification after a host accepts their invitation to an event.  It ensures the notification is received promptly, displays the correct information, and links to the relevant section within the application.

*   **Steps:**

    1.  **Precondition:** User A (the Guest) exists and is logged into the application. User B (the Host) exists and is logged into the application. User B has created an event and sent an invitation to User A. User A has the application open (or backgrounded but connected to receive push notifications). User A has not yet responded to the invitation.
    2.  User B (the Host) navigates to the "Guestlist" section of the event they created.
    3.  User B locates User A's pending invitation.
    4.  User B clicks the "Accept" button for User A's invitation.
    5.  User A (the Guest) waits for a notification to appear on their device or within the application (if push notifications are disabled).
    6.  Observe the notification content.
    7.  Click/Tap on the notification.
    8. Observe the resulting page or section within the application.

*   **Expected Result:**

    1.  **Notification is Received:** Within a reasonable timeframe (e.g., within 5-10 seconds), User A should receive a push notification and/or an in-app notification.
    2.  **Correct Notification Content:** The notification should display the following information accurately:
        *   A clear message indicating acceptance (e.g., "Your invitation to [Event Name] has been confirmed!").
        *   The name of the event ([Event Name]).
        *   The name of the host (User B, if space allows).
    3.  **Link to Event Details:**  Clicking the notification should navigate User A to the event details page within the application, specifically to the section relevant to their guest status (e.g., a confirmed guest list view, or the general event details with their confirmed status highlighted).
    4.  **Notification Persistence:** The notification should persist within the app's notification center until dismissed.
    5.  **Visual consistency:** The notification should follow the defined app style guide, and branding of the app should be present within the notification.

*   **Priority:** High

**Test Case 2: Successfully Deleted Notification - Host Perspective**

*   **Title:** Verify Host Receives Successful Guest Deletion Notification

*   **Description:** This test case verifies that a host receives a confirmation notification after successfully deleting a guest from their guestlist for a specific event. This ensures the host is informed that their action was successfully processed.

*   **Steps:**

    1.  **Precondition:** User B (the Host) exists and is logged into the application. User A (the Guest) exists and is also logged in the application. User B has created an event and User A is already on the guestlist for that event.
    2.  User B navigates to the "Guestlist" section of the event they created.
    3.  User B locates User A on the guestlist.
    4.  User B selects the "Delete" or "Remove" action for User A from the guestlist.
    5.  User B confirms the deletion if a confirmation prompt is presented (e.g., "Are you sure you want to remove [Guest Name] from the guestlist?").
    6.  User B waits for a notification to appear on their device or within the application (if push notifications are disabled).
    7.  Observe the notification content.

*   **Expected Result:**

    1.  **Notification is Received:** Within a reasonable timeframe (e.g., within 5-10 seconds), User B should receive a push notification and/or an in-app notification.
    2.  **Correct Notification Content:** The notification should display the following information accurately:
        *   A clear message indicating successful deletion (e.g., "[Guest Name] has been successfully removed from the guestlist for [Event Name].").
        *   The name of the guest that was removed ([Guest Name]).
        *   The name of the event ([Event Name]).
    3.  **Notification Persistence:** The notification should persist within the app's notification center until dismissed.
    4.  **Optional:** Verify that the Guest has been successfully removed from the guestlist in the app.
    5.  **Visual consistency:** The notification should follow the defined app style guide, and branding of the app should be present within the notification.

*   **Priority:** Medium

**Important Considerations (Applicable to All Test Cases):**

*   **Notification Delivery Reliability:**  It's important to consider the reliability of the notification delivery infrastructure (e.g., APNS for iOS, FCM for Android).  If the notifications are consistently delayed or not delivered, it indicates a serious problem.
*   **Platform Differences:** Test on various devices and operating system versions (iOS and Android) to ensure consistent behavior. Notifications can render differently across platforms.
*   **Background Operation:**  Ensure notifications are received even when the app is in the background or closed (especially on Android, where background restrictions are stricter).
*   **Edge Cases:** Consider edge cases such as:
    *   What happens if the user has disabled notifications for the app?
    *   What happens if the user has poor internet connectivity?
    *   What happens if there is a server-side error during the guest removal/acceptance process?
*   **Internationalization:** If the application supports multiple languages, verify that the notification content is correctly localized.
*   **Performance:**  Monitor the performance impact of generating and sending notifications, especially under heavy load.
*   **Security:**  Ensure the notifications do not expose any sensitive information or vulnerabilities.

These test cases provide a solid starting point. Remember to adapt them and create additional test cases based on the specific requirements and design of your guestlist notification feature. Good luck!
