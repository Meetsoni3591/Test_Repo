# Test Cases for T5.1.1 - Create/Update User

Okay, here are two detailed test cases for the "Create/Update User" task, focusing on different aspects of the functionality:

**Test Case 1:  Valid User Creation with All Optional Referral Information**

*   **Title:** Create New User with All Personal Details and Referral Information

*   **Description:** This test case verifies that a new user can be successfully created with all required personal details and all optional referral information fields populated with valid data. This tests the positive scenario of a complete user creation process.

*   **Steps:**

    1.  Navigate to the User Management screen (e.g., `/admin/users`).
    2.  Click the "Create User" or "Add User" button (or equivalent).
    3.  Enter a valid first name in the "First Name" field (e.g., "John").
    4.  Enter a valid last name in the "Last Name" field (e.g., "Doe").
    5.  Enter a valid email address in the "Email" field (e.g., "john.doe@example.com").
    6.  Enter a valid phone number in the "Phone Number" field (e.g., "555-123-4567").
    7.  Select "Member" from the "Status" dropdown.
    8.  Populate all Referral Information fields with valid data:
        *   Referral Source (e.g., "Friend")
        *   Referrer Name (e.g., "Jane Smith")
        *   Referrer Email (e.g., "jane.smith@example.com")
    9.  Click the "Save" or "Create User" button.
    10. Verify data is saved correctly in the database.

*   **Expected Result:**

    1.  The user is successfully created.
    2.  A success message is displayed (e.g., "User created successfully").
    3.  The newly created user appears in the User Management list with the correct details (Name, Email, Phone Number, Status, and referral source).
    4.  The user details are correctly stored in the database, including all personal and referral information, and the status is "Member".
    5.  There are no error messages displayed on the screen.

*   **Priority:** High

**Test Case 2:  Update User Status with Invalid Email Format**

*   **Title:** Update Existing User's Status with Invalid Email Format

*   **Description:** This test case validates the system's ability to handle invalid email formats when updating an existing user's details. It focuses on data validation and error handling for the "Email" field during user updates.

*   **Steps:**

    1.  Navigate to the User Management screen (e.g., `/admin/users`).
    2.  Locate an existing user in the user list.
    3.  Click the "Edit" or "Update" button (or equivalent) next to the selected user.
    4.  Change the existing email address to an invalid format in the "Email" field (e.g., "johndoeexample.com" or "john.doe@example").
    5.  Select "Waitlist" from the "Status" dropdown.
    6.  Click the "Save" or "Update User" button.

*   **Expected Result:**

    1.  The user details are not updated.
    2.  The system displays an appropriate error message near the "Email" field, indicating that the email address is invalid (e.g., "Please enter a valid email address").
    3.  The "Status" of the user should not be updated to "Waitlist".
    4.  The user details in the user list remain unchanged.
    5.  The error message is clear, concise, and guides the user on how to correct the input.
    6.  No updates are made to the database.

*   **Priority:** High

**Explanation of Choices and Considerations:**

*   **Focus on Key Functionality:** These test cases cover both user creation and updating, and they address both the positive (successful creation) and negative (validation of invalid data) scenarios.
*   **Boundary Conditions:** The email validation test case is important because email fields are prone to input errors and are critical for user identification.
*   **Referral Information:**  We specifically test the referral information as it's mentioned in the task description and often involves a separate database table or data structure.
*   **Priority:**  Both tests are marked as "High" because they directly impact the core functionality of creating and managing user accounts.  A failure in either area would significantly impact the application's usability and data integrity.
*   **Clear Steps and Expectations:**  The steps are specific and unambiguous, and the expected results are clearly defined to allow for consistent and objective evaluation of the test results.
*   **Database Verification:** It is important to verify that the correct data exists in the database after creating a new user.
*   **Edge Cases:** We can also add edge cases, such as a very long name or email address.

These test cases can be further expanded upon to cover additional scenarios, such as:

*   Testing different "Status" options.
*   Testing the handling of duplicate email addresses.
*   Testing required fields (ensuring error messages are displayed when required fields are left blank).
*   Testing the length and character limits of the various fields.
