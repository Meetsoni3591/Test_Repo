# Test Cases for T5.2.1 - Invite User

Okay, here are two detailed test cases for the "Invite User" feature, focusing on different aspects of the described functionality. I've aimed for good coverage, considering potential edge cases and common user flows.

**Test Case 1: Invite User via Email - Successful Invitation and Acceptance**

*   **Title:** Invite User - Email Invitation, Successful Acceptance

*   **Description:** This test case verifies the successful invitation of a new user via email, the proper generation and sending of the invitation email, and the successful account creation and login by the invited user through the invitation link.

*   **Steps:**

    1.  **Pre-condition**: User is logged into the application with the required permissions to invite new users (e.g., 'Admin', 'Manager').
    2.  Navigate to the "Invite User" section of the application.
    3.  Select the "Invite by Email" option.
    4.  Enter a valid, unused email address (e.g., `testuser+invitation1@example.com`). *Note: Using a unique email address for each test run is crucial to avoid conflicts.*
    5.  Enter the required information of the new user (e.g., First Name, Last Name, Role).  For this case, assign a basic role such as "Contributor".
    6.  Click the "Send Invitation" button.
    7.  **Verification:** Observe the on-screen confirmation message indicating that the invitation was sent successfully.
    8.  **Verification:** Check the invitation status in the user interface, such as a list of invitations. It should show as "Pending".
    9.  **External Action:** Access the email inbox of the specified email address (`testuser+invitation1@example.com`).
    10. **Verification:** Verify that the invitation email has been received.
    11. **Verification:** Ensure the email subject is correct (e.g., "You're invited to join [Application Name]!").
    12. **Verification:** Verify the email body contains the correct message, including the sender name and the application name.
    13. Verify that the invitation email contains a unique invitation link/button.
    14. Click the invitation link/button in the email.
    15. Verify that the link redirects to the account creation page within the application.
    16. Enter the required information for account creation (e.g., Password, Confirm Password).
    17. Accept the terms and conditions (if applicable).
    18. Click the "Create Account" or "Sign Up" button.
    19. Verify the user is automatically logged in to the application.
    20. Navigate to the "Users" or "User Management" section in the app as admin/manager.
    21. **Verification:** Confirm that the newly created user account is present in the system.
    22. **Verification:** Verify that the user role is correctly assigned (e.g., "Contributor").
    23. **Verification:** Confirm that the invitation status now shows as "Accepted" in the invite management screen.

*   **Expected Result:**

    *   The invitation is sent successfully, and a confirmation message is displayed.
    *   The invitation status in the user interface is updated to "Pending" initially and then to "Accepted" after account creation.
    *   The invitation email is received by the specified email address, containing accurate information and a valid invitation link.
    *   The invitation link redirects to the account creation page.
    *   The user can successfully create an account and log in to the application.
    *   The newly created user account appears in the user management section with the correct role.

*   **Priority:** High

**Test Case 2: Invite User - Email - Invalid Scenarios and Error Handling**

*   **Title:** Invite User - Email - Invalid Input and Error Handling

*   **Description:** This test case verifies the system's behavior when attempting to invite users with invalid email addresses, duplicate email addresses, missing required fields, and under various other error conditions. It focuses on error message accuracy, preventing invalid data entry, and maintaining system stability.

*   **Steps:**

    1.  **Pre-condition**: User is logged into the application with the required permissions to invite new users.
    2.  Navigate to the "Invite User" section of the application.
    3.  Select the "Invite by Email" option.

    **Scenario 1: Invalid Email Format**

    4.  Enter an invalid email address format (e.g., "testuser@example", "testuser.com").
    5.  Enter other required information (e.g., First Name, Last Name, Role).
    6.  Click the "Send Invitation" button.
    7.  **Expected Result:** An appropriate error message is displayed, indicating that the email address format is invalid (e.g., "Invalid email address format").  The invitation should not be sent.

    **Scenario 2: Duplicate Email Address**

    8.  Enter an email address that already exists in the system (either as a registered user or a previously invited user). *Important: Use an email address you know is already in the system from previous tests.*
    9.  Enter other required information (e.g., First Name, Last Name, Role).
    10. Click the "Send Invitation" button.
    11. **Expected Result:** An error message is displayed, indicating that the email address is already in use (e.g., "Email address already exists"). The invitation should not be sent.

    **Scenario 3: Missing Required Fields**

    12. Leave one or more required fields blank (e.g., First Name, Last Name, Role).
    13. Enter a valid email address.
    14. Click the "Send Invitation" button.
    15. **Expected Result:** An error message is displayed, indicating which required fields are missing (e.g., "First Name is required", "Role is required"). The invitation should not be sent. The missing fields should be clearly highlighted (e.g., red outline, asterisk).

    **Scenario 4:  Email Address Exceeding Maximum Length**

    16. Enter an email address that exceeds the maximum allowed length (e.g., a very long string @example.com).
    17. Enter other required information (e.g., First Name, Last Name, Role).
    18. Click the "Send Invitation" button.
    19. **Expected Result:** An error message is displayed indicating that the email address length exceeds the limit (e.g., "Email address is too long"). The invitation should not be sent.

    **Scenario 5:  Role Assignment Invalid**

    20. Select or enter a role that is not a valid role in the system (e.g., a non-existent role ID or a string that is not a recognized role).
    21. Enter a valid email address and other required information.
    22. Click the "Send Invitation" button.
    23. **Expected Result:** An error message should be displayed, indicating the role is invalid (e.g., "Invalid Role Selection"). The invitation should not be sent.

    **Scenario 6: Attempt to Resend Invitation to an Accepted User**

    24. From the Invite Management Section, attempt to resend invitation to an email whose invite status is already "Accepted."
    25. **Expected Result:** System shouldn't allow resending the invite. Error message should indicate "Invite can't be sent as the user is already active"

*   **Priority:** High
