# Test Cases for T5.2.2 - Activate User

Okay, here are two detailed test cases based on the "Activate User" task, covering both manual and automated approval scenarios.  I've focused on boundary conditions and common failure points.

**Test Case 1: Manual User Activation - Approved via Admin Panel**

*   **Title:** Verify Successful Manual User Activation and Membership Confirmation
*   **Description:** This test case verifies that a user registered with manual approval required can be successfully activated by an administrator through the admin panel, and that the user receives the appropriate confirmation and gains expected membership privileges upon activation.
*   **Steps:**

    1.  **Precondition:**  Ensure a user registration setting is configured for "Manual Approval" required.
    2.  **Register a New User:**  Submit a new user registration form with valid credentials (email, username, password, etc.).  Record the username and email address used.
    3.  **Verify Registration Confirmation:** Confirm that a registration confirmation email is sent to the email address provided during registration with appropriate instructions.
    4.  **Login to Admin Panel:** Login to the application's administrative panel using valid administrator credentials.
    5.  **Navigate to User Management:** Navigate to the user management section of the admin panel (e.g., "Users," "Pending Approvals," etc.).
    6.  **Locate Pending User:** Locate the newly registered user in the list of pending approvals using the username or email address.
    7.  **Initiate Manual Activation:** Select the user and initiate the manual activation process (e.g., click an "Approve" button, change the user status to "Active", etc.).
    8.  **Verify Confirmation Message:**  Confirm that a success message is displayed in the admin panel indicating successful user activation.
    9.  **Check User Status in Admin Panel:** Verify that the user's status in the user management section of the admin panel is updated to "Active" or the appropriate equivalent.
    10. **Verify Activation Email:** Verify that the registered user receives an activation confirmation email, typically including a welcome message and login instructions.
    11. **Attempt User Login:** Log in to the application with the newly activated user's credentials.
    12. **Verify Membership Access:** Verify that the user can successfully log in and access the appropriate sections of the application based on the assumed default membership level (or any explicitly configured default membership).
    13. **Check Default Membership Privileges:** Check that the user has access to the expected features and resources associated with the default membership.
*   **Expected Result:**

    1.  User registration confirmation email is received by the user.
    2.  Administrator can successfully approve the user through the admin panel.
    3.  A success message confirms successful activation in the admin panel.
    4.  User status is updated to "Active" in the admin panel.
    5.  User receives an activation confirmation email.
    6.  User can successfully log in to the application.
    7.  User can access the expected sections of the application as per the default membership level.
    8.  User has appropriate default membership privileges.
*   **Priority:** High

**Test Case 2: Automated User Activation - Check Email Verification**

*   **Title:** Verify Successful Automated User Activation via Email Verification
*   **Description:** This test case verifies that a user registered with automated approval (requiring email verification) can successfully activate their account by clicking the verification link in the confirmation email, and that the user receives appropriate confirmation and membership privileges upon activation. This test case also covers cases where the link could have expired.
*   **Steps:**

    1.  **Precondition:** Ensure a user registration setting is configured for "Automated Approval" required with "Email Verification" enabled.  Also, note the default expiration time for the verification link.
    2.  **Register a New User:** Submit a new user registration form with valid credentials (email, username, password, etc.). Record the username and email address used.
    3.  **Verify Registration Email:** Confirm that a registration confirmation email is sent to the email address provided during registration, containing a verification link.
    4.  **Click Verification Link:** Click the verification link in the email.  Observe the resulting page or message.
    5.  **Verify Successful Activation Message:** Verify that a success message is displayed on the page after clicking the link, indicating successful user activation. This message should be clear and user-friendly.
    6.  **Attempt User Login:** Log in to the application with the newly activated user's credentials.
    7.  **Verify Membership Access:** Verify that the user can successfully log in and access the appropriate sections of the application based on the assumed default membership level (or any explicitly configured default membership).
    8.  **Check Default Membership Privileges:** Check that the user has access to the expected features and resources associated with the default membership.
    9.  **Expire the link (Time out test):** Wait for the verification link expiration time to pass (e.g., 24 hours if that's the configured expiration).
    10. **Click Expired Verification Link:** Click the SAME verification link in the email after the expiration time has passed.
    11. **Verify Expiration Error Message:** Verify that a clear and user-friendly error message is displayed, indicating that the verification link has expired. The message should instruct the user on how to proceed (e.g., request a new verification email).
    12. **Attempt User Login (After Expiration):** Attempt to log in to the application with the user's credentials.
    13. **Verify Login Failure (After Expiration):** Verify that the login attempt fails, and a message is displayed indicating that the user's account is not yet activated or that they need to verify their email.

*   **Expected Result:**

    1.  User registration confirmation email containing a verification link is received.
    2.  Clicking the verification link before expiration leads to a successful activation message and activation of the user account.
    3.  User can successfully log in to the application after activating via the link.
    4.  User has access to the expected sections of the application as per the default membership level.
    5.  User has appropriate default membership privileges.
    6.  Clicking the expired verification link leads to an appropriate error message, indicating the link has expired.
    7.  Login fails after the verification link has expired.

*   **Priority:** High
