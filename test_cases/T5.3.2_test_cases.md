# Test Cases for T5.3.2 - Referral Rewards

Okay, here are two detailed test cases for the "Referral Rewards" task, designed for a senior QA engineer to execute.  I've focused on testing core functionality and potential edge cases:

**Test Case 1: Successful Referral and Reward Allocation**

*   **Title:** Verify Successful Referral Process and Reward Allocation to Referrer and Referee

*   **Description:** This test case validates the core referral functionality: a user refers a new user, the new user signs up, and both the referrer and referee receive the correct reward according to the defined system (e.g., points). It covers both point assignment and correct user association with the referral.

*   **Steps:**

    1.  **Setup:**
        *   Ensure the Referral Rewards system is enabled and configured (check configuration settings for reward amounts, referral codes, etc.).
        *   Create two new, distinct test user accounts (e.g., `referrer_test_user@example.com` and `referee_test_user@example.com`).  Ensure neither account has been previously used for referrals.
        *   Log in as `referrer_test_user@example.com`.
    2.  **Initiate Referral:**
        *   Navigate to the referral section (as defined in the UI).
        *   Obtain the unique referral code/link for `referrer_test_user@example.com`.
    3.  **Referee Sign-Up:**
        *   Log out of `referrer_test_user@example.com`.
        *   Open a new browser or use a private browsing window to avoid session conflicts.
        *   Use the referral link/code from step 2 to sign up as `referee_test_user@example.com`.  Complete the sign-up process, providing all required information.
        *   Complete any necessary verification steps (e.g., email confirmation).
    4.  **Post Sign-Up Actions for Referee (if required):**
        *   If the referral reward is contingent on the referee completing a specific action (e.g., making a purchase, reaching a certain level, adding payment info), perform that action as `referee_test_user@example.com`.  Record the time and details of this action.
    5.  **Verify Referrer Reward:**
        *   Log out of `referee_test_user@example.com`.
        *   Log back in as `referrer_test_user@example.com`.
        *   Navigate to the user's account balance or reward history section (as defined in the UI).
        *   Check for an entry indicating a reward was granted for the successful referral of `referee_test_user@example.com`.
        *   Verify the reward amount is correct according to the configured settings.
        *   Verify the date and time of the reward align with the referee's sign-up/qualifying action time.
    6.  **Verify Referee Reward:**
        *   Log out of `referrer_test_user@example.com`.
        *   Log in as `referee_test_user@example.com`.
        *   Navigate to the user's account balance or reward history section.
        *   Check for an entry indicating a reward was granted for signing up through a referral.
        *   Verify the reward amount is correct.
        *   Verify the date and time of the reward align with their sign-up time.
    7.  **Database Verification (Optional but Recommended):**
        *   Directly query the database to verify the referral relationship between `referrer_test_user@example.com` and `referee_test_user@example.com` is correctly recorded.
        *   Verify the reward balances for both users are accurately reflected in the database.

*   **Expected Result:**

    *   `referee_test_user@example.com` is successfully created and associated with the referral code of `referrer_test_user@example.com`.
    *   `referrer_test_user@example.com` receives the configured referral reward (e.g., points) in their account balance and reward history within a reasonable timeframe (as defined by the system).
    *   `referee_test_user@example.com` receives the configured reward for signing up through a referral in their account balance and reward history.
    *   Database records accurately reflect the referral relationship and reward balances for both users.

*   **Priority:** High

**Test Case 2: Referral Code Tampering and Invalid Scenarios**

*   **Title:** Validate Referral Code Tampering Prevention and Error Handling

*   **Description:** This test case focuses on security and robustness. It aims to verify that the system handles invalid or tampered referral codes gracefully and prevents exploitation or unintended behavior.  It covers cases where a user attempts to manipulate the referral code to gain unauthorized rewards or bypass the intended referral process.

*   **Steps:**

    1.  **Setup:**
        *   Ensure the Referral Rewards system is enabled and configured.
        *   Create a new test user account (`tamper_test_user@example.com`).
        *   Log in as `tamper_test_user@example.com`.
        *   Obtain the unique referral code/link for `tamper_test_user@example.com`.

    2.  **Tamper with Referral Code:**
        *   Modify the referral code/link obtained in step 1 in the following ways (perform each modification as a separate sub-test):
            *   **Case 1: Invalid Characters:** Add special characters or invalid characters to the referral code (e.g., `code!@#$%^`, `code with spaces`).
            *   **Case 2: Code Truncation:** Shorten the referral code.
            *   **Case 3: Code Extension:** Add extra characters to the end of the referral code.
            *   **Case 4: Existing User Code:** Use the referral code of an existing user that is not `tamper_test_user@example.com` (create a new user to get a valid code)
            *   **Case 5: Reused Code:** Use the same code twice.
        *   Attempt to sign up a *new* user account using the modified referral code/link in each case.  (e.g. newuser1@example.com)

    3.  **Attempt Direct Reward Manipulation (if possible - depends on system design):**
        *   Inspect the network requests during the referral sign-up process.  Look for any parameters related to the referral code or reward allocation.
        *   Attempt to directly modify these parameters using browser developer tools (e.g., intercept and modify the POST request).
        *   Submit the modified request.

    4.  **Verify Error Handling and Prevention:**
        *   For each attempt to use a tampered or invalid referral code, observe the system's response.

*   **Expected Result:**

    *   **For Tampered Codes (Step 2):**
        *   The system *must* reject the tampered or invalid referral code.
        *   The new user account registration *must* fail (or proceed without applying the referral reward).
        *   An appropriate error message should be displayed to the user, indicating that the referral code is invalid.  The error message should not be overly specific to avoid revealing details about the referral code structure.
        *   The system should *not* grant any referral rewards to either the new user or the user associated with the tampered code.
    *   **For Direct Reward Manipulation (Step 3):**
        *   The system *must* prevent the direct manipulation of reward parameters.
        *   The modified request should be rejected, or the changes should be ignored.
        *   No unauthorized rewards should be granted.
        *   Appropriate security measures (e.g., server-side validation, authentication checks) should be in place to prevent this type of attack.
    *   The referral process should not be corrupted or destabilized by these attempts.
    *   No exceptions or errors should be logged on the server-side due to these invalid attempts.

*   **Priority:** High

**Important Considerations for Both Test Cases:**

*   **Reward Types:** The test cases assume a point-based system. Adjust the steps and expected results if a different reward system is used (e.g., discounts, free trials).
*   **Terms and Conditions:** If the referral program has specific terms and conditions (e.g., limitations on the number of referrals, expiration dates), create additional test cases to verify adherence to those terms.
*   **UI/UX:** While these test cases focus on core functionality, also consider creating separate test cases for UI/UX aspects, such as the clarity of the referral instructions, the visibility of rewards, and the ease of use of the referral process.
*   **Scalability:**  Consider creating performance tests to ensure the referral system can handle a large volume of referrals without performance degradation.
*   **Logging and Monitoring:**  Verify that all referral activities are properly logged and monitored for auditing and fraud detection purposes.
*   **Integration:** Test the integration with other systems, such as user management, payment processing, and email services.
*   **Edge Cases:**  Continue to brainstorm additional edge cases based on the specific implementation of the referral rewards system.

By following these test cases, you can ensure that the referral rewards system is working as intended, secure, and provides a positive experience for both referrers and referees. Remember to document all test results and report any defects found.
