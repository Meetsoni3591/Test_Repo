# Test Cases for T5.3 - Referral Tracking

Okay, I can do that. Here are two detailed test cases designed for the "Referral Tracking" feature, covering different aspects of its functionality.

**Test Case 1: Successful Referral Creation and Tracking**

*   **Title:** Verify Successful Referral Creation and Tracking from User Dashboard
*   **Description:** This test case verifies that a user can successfully generate a referral link from their dashboard, and that a new referral is properly tracked when a new user signs up using that link.
*   **Steps:**

    1.  **Pre-condition:**
        *   A valid user account exists in the system.
        *   The user is logged into the application.
        *   Referral feature is enabled in the application.
    2.  **Navigation:** Navigate to the user's dashboard or profile page where the referral link generation option is located.
    3.  **Generate Referral Link:** Click on the button or link to "Generate Referral Link" or similar. If there are different options, such as selecting a specific reward or customizing the referral message, choose one option.
    4.  **Copy Referral Link:** Copy the generated referral link to the clipboard.
    5.  **Open Incognito/Private Browser Window:** Open a new incognito/private browser window. This ensures no existing user sessions interfere with the test.
    6.  **Paste and Navigate:** Paste the copied referral link into the address bar of the incognito browser window and navigate to the URL.
    7.  **Sign Up with New Account:** On the landing page, create a brand new user account using a unique email address and other required details. Ensure all required fields are filled correctly.
    8.  **Post-condition:** Log in to the newly created account.
    9.  **Verify Referral Status:** Log back into the original user account (the one that generated the referral link). Navigate to the referral tracking section of the dashboard or profile.
    10. **Check Referral Count:** Verify that the referral count has increased.
*   **Expected Result:**

    *   Step 3: A unique referral link is generated and displayed to the user.
    *   Step 4: The referral link is copied correctly.
    *   Step 7: A new user account is successfully created through the referral link.
    *   Step 9: The referral tracking section correctly reflects that a new referral has been made.
    *   Step 10: The referral count has increased by one. If applicable, the referral tracking section shows the new user's information (e.g., username, sign-up date/time) and referral status (e.g., "Pending", "Approved", "Completed"). If there is referral reward, then it will show the correct referral reward type.
*   **Priority:** High

**Test Case 2: Referral Link Validation and Error Handling**

*   **Title:** Verify Invalid Referral Link Handling
*   **Description:** This test case verifies that the system correctly handles invalid or expired referral links, preventing unintended behavior and providing informative error messages to users.
*   **Steps:**

    1.  **Pre-condition:**
        *   The referral feature is enabled in the application.
    2.  **Craft Invalid Link:** Manually create an invalid referral link by:
        *   Changing the referral code to a non-existent code.
        *   Removing or adding characters to the referral link.
        *   Modifying the domain.
        *   If there is an expiry date, create an expired referral link.
    3.  **Navigate to Invalid Link:** Paste the crafted invalid referral link into the address bar of a browser and navigate to the URL.  Use an incognito browser to avoid any session interference.
    4.  **Attempt Signup:** If the user is able to navigate to a signup page after step 3, attempt to sign up.
*   **Expected Result:**

    *   Step 3: An error message is displayed to the user, indicating that the referral link is invalid or expired. The page should not redirect to a signup or login page without proper validation.
    *   Step 4: An error message stating that the referral link is invalid is shown to the user.
*   **Priority:** High

**Explanation of Choices:**

*   **Priority:** Both test cases are marked as "High" because they directly impact the core functionality of the referral tracking system. A broken or easily exploitable referral system can lead to inaccurate data, user frustration, and potential financial losses (if rewards are involved).
*   **Comprehensive Coverage:** These two test cases cover essential aspects: the successful creation and tracking of referrals, and the proper handling of invalid links. This provides a good foundation for testing the feature.
*   **Detailed Steps:** The steps are broken down into small, manageable actions, making it easier for testers to follow and identify the exact point of failure.
*   **Clear Expected Results:** Each step has a clearly defined expected result, making it easy to determine whether the test passed or failed.
*   **Real-World Scenarios:** The test cases are designed to simulate real-world scenarios, such as users sharing links and attempting to use invalid links.
*   **Error Handling:** Test case 2 focuses on error handling, which is often overlooked but crucial for a robust application.

These are just two examples; more test cases can be created to cover other scenarios, such as:

*   Testing referral rewards and their distribution
*   Testing different referral types (e.g., one-time use, multi-use)
*   Testing referral limits (if any)
*   Testing the referral dashboard for accurate reporting
*   Testing the impact of referrals on system performance.
*   Testing that the feature is compatible with different browsers and devices.
*   Testing that the feature is accessible for all types of users.

Remember to adapt and expand on these test cases based on the specific requirements and complexity of your application.
