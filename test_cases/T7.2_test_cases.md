# Test Cases for T7.2 - Venue Manager Role

Okay, here are two detailed test cases for the Venue Manager role, focusing on limited access as described in the task.

**Test Case 1: Venue Manager - Read-Only Access to Venue Profile Details**

*   **Title:** Venue Manager - Verify Read-Only Access to Venue Profile Details

*   **Description:** This test case verifies that a user with the "Venue Manager" role can view, but not modify, key venue profile details such as name, address, description, and contact information. This ensures data integrity and prevents unauthorized changes to core venue information.

*   **Steps:**

    1.  **Login:** Log in to the application as a user with the "Venue Manager" role, associated with a specific venue (e.g., "The Grand Ballroom").
    2.  **Navigate:** Navigate to the "Venues" section of the application.
    3.  **Select Venue:** Locate and select "The Grand Ballroom" from the list of venues.
    4.  **Access Venue Details:** Navigate to the "Details" or "Profile" tab/section of the venue's page.
    5.  **Inspect Fields:** Inspect the following fields/elements on the venue profile page:
        *   Venue Name
        *   Venue Address (Street, City, State, Zip Code)
        *   Venue Description
        *   Contact Person Name
        *   Contact Phone Number
        *   Contact Email Address
        *   Any other customizable fields (e.g., website, social media links).
    6.  **Attempt to Edit:** Attempt to edit any of the fields mentioned in step 5 by clicking on them, trying to input data, or looking for edit/update buttons.  Specifically, look for common UI elements that allow for editing such as:
        *   Pencil icon
        *   Edit button
        *   Editable text boxes

*   **Expected Result:**

    *   The Venue Manager can view all the venue profile details (Venue Name, Venue Address, Venue Description, Contact Information, etc.) without any issues.
    *   All fields mentioned in step 5 should be displayed as read-only. The Venue Manager should not be able to modify any of these fields.
    *   No edit buttons, pencil icons, or other interactive elements that would allow editing of the venue details should be present.
    *   The application should not display any error messages related to permission issues.

*   **Priority:** High
    *   This is a core access control requirement.  Failure indicates a serious security flaw.

**Test Case 2: Venue Manager - Limited Access to Event Management within Assigned Venue**

*   **Title:** Venue Manager - Verify Event Management Access within Assigned Venue

*   **Description:** This test case verifies that a user with the "Venue Manager" role can create, view, and modify events associated with their assigned venue but cannot access or modify events related to other venues.  It also verifies that they have appropriate permissions for event details.

*   **Steps:**

    1.  **Login:** Log in to the application as a user with the "Venue Manager" role, associated with a specific venue (e.g., "The Grand Ballroom").
    2.  **Navigate:** Navigate to the "Events" section of the application.
    3.  **View Events:** Verify that the list of events displayed is filtered to show only events scheduled at "The Grand Ballroom".
    4.  **Attempt to View Other Venues' Events:** Attempt to access events associated with a different venue (e.g., "The Rooftop Terrace").  This may involve searching for events by venue, using a dropdown filter, or directly navigating to a specific event URL (if possible).
    5.  **Create New Event:** Create a new event within the "Events" section.
    6.  **Verify Venue Association:** Confirm that the new event is automatically associated with "The Grand Ballroom" and that the Venue Manager cannot change this association.
    7.  **Edit Event Details:** Open an existing event associated with "The Grand Ballroom" and verify the following edit functionalities:
        *   **Allowed:**  Ability to edit the event's description, start/end times, capacity, and assigned staff (if applicable).
        *   **Restricted:**  Inability to change the event's assigned venue.  Inability to access or modify financial details like ticket pricing (this likely belongs to a different role, such as "Event Planner" or "Finance Manager").
    8.  **Delete Event:** Verify that the Venue Manager has the ability to delete events.
    9. **View Stats:** Navigate to the "Stats" section and verify that the Venue Manager only see the stats related to his assigned venue.

*   **Expected Result:**

    *   The Venue Manager can only view events that are scheduled for their assigned venue ("The Grand Ballroom").
    *   When attempting to view events for other venues ("The Rooftop Terrace"), the application should either prevent access (e.g., by displaying an "Unauthorized" error), or redirect them back to their assigned venue's event list.
    *   When creating a new event, the event is automatically associated with "The Grand Ballroom," and this association cannot be changed by the Venue Manager.
    *   The Venue Manager can edit allowed event details (description, times, capacity, staff) but cannot change the assigned venue or access financial details.
    *   The Venue Manager can delete events associated to his assigned venue
    *   The Venue Manager only see the stats related to his assigned venue.

*   **Priority:** High
    *   Ensuring proper event access control is critical for data security and prevents unauthorized modification of events.
    *   Failure to restrict venue association during event creation or editing represents a significant security vulnerability.
